# Vitara: ร้านอาหารเสริมออนไลน์

เว็บขายอาหารเสริมแบบครบวงจร มีทั้งหน้าร้าน (React) และระบบหลังบ้าน (Node.js + Express + SQLite) พร้อมผู้ช่วย AI (Claude) ที่แนะนำสินค้าตามเป้าหมาย อายุ เพศ และงบประมาณ

## ความสามารถ

**หน้าร้าน**
- ค้นหาสินค้า (รองรับภาษาไทย) กรองตามหมวด ช่วงอายุ เพศ ราคา สินค้าพร้อมส่ง และเรียงลำดับได้ ตัวกรองทั้งหมดอยู่ใน URL จึงแชร์ลิงก์ผลการค้นหาได้
- หน้าสินค้า: รายละเอียด ส่วนประกอบ วิธีทาน คำเตือน รีวิวพร้อมสรุปคะแนน และสินค้าที่คล้ายกัน
- ตะกร้าเก็บไว้ที่เซิร์ฟเวอร์ ลูกค้าที่ยังไม่ล็อกอินก็ใช้ได้ และตะกร้าจะรวมเข้าบัญชีอัตโนมัติเมื่อล็อกอิน
- ชำระเงินได้ 3 แบบ: พร้อมเพย์ บัตรเครดิต (ผ่าน Stripe) และเก็บเงินปลายทาง มีโค้ดส่วนลด และส่งฟรีเมื่อซื้อครบ ฿990
- หน้าติดตามคำสั่งซื้อพร้อมไทม์ไลน์สถานะ ลูกค้าที่สั่งโดยไม่ล็อกอินเปิดดูได้ด้วยลิงก์ลับของคำสั่งซื้อนั้น
- สมัครสมาชิก เข้าสู่ระบบ ดูประวัติคำสั่งซื้อ แก้ไขข้อมูลส่วนตัว และเปลี่ยนรหัสผ่าน
- เขียนรีวิวได้เมื่อล็อกอิน รีวิวจากคนที่ซื้อสินค้านั้นจริงจะมีป้าย "ผู้ซื้อจริง"
- **ผู้ช่วย AI "น้องวี"**: ลูกค้าพิมพ์เป้าหมาย เช่น "อยากได้อาหารเสริมผิวขาว" และเลือกตัวกรองอายุ เพศ งบประมาณได้ ระบบจะแนะนำสินค้า 1–3 รายการพร้อมเหตุผล และกดใส่ตะกร้าจากในแชทได้เลย
- **แบบทดสอบสุขภาพ** (`/quiz`): ตอบ 8 คำถาม (อายุ เป้าหมาย การนอน การออกกำลังกาย หน้าจอ การกิน ภาวะสุขภาพ งบต่อเดือน) แล้วได้ชุดอาหารเสริม 2–4 ชิ้นที่ไม่เกินงบ พร้อมตารางเวลาทาน คำแนะนำไลฟ์สไตล์ และคำเตือนเมื่อตั้งครรภ์หรือใช้ยา กดใส่ตะกร้าทั้งชุดได้ในคลิกเดียว ถ้าตั้งค่า Claude ไว้จะใช้ AI จัดชุด ถ้าไม่ได้ตั้งจะใช้กฎที่เขียนไว้
- **สมัครรับประจำ (Subscribe & Save)**: เลือกให้ส่งทุก 30/60/90 วัน ได้ส่วนลด 10% (ปรับได้) ระบบจะสร้างคำสั่งซื้อรอบใหม่ให้ก่อนวันส่ง 3 วัน และส่งอีเมลแจ้ง ถ้าจ่ายแบบปลายทางจะจัดส่งเลย ถ้าจ่ายด้วยบัตรหรือพร้อมเพย์จะส่งลิงก์ให้ชำระ ลูกค้าเปลี่ยนรอบ จำนวน หรือวิธีชำระ และข้ามรอบ พัก หรือยกเลิกได้เองในหน้าบัญชี
- **เตือนสินค้าใกล้หมด**: คำนวณจากวันที่สั่งและจำนวนวันที่สินค้า 1 ชิ้นใช้ได้ ส่งอีเมลเตือนก่อนหมด 5 วัน ในหน้าบัญชีมีแท็บ "ใกล้หมด" พร้อมปุ่มสั่งซ้ำ และทุกคำสั่งซื้อมีปุ่ม "ซื้ออีกครั้ง"
- **รูปสินค้าหลายรูป**: มีแกลเลอรีพร้อมรูปย่อ คลิกเพื่อดูเต็มจอและซูมได้
- **อีเมล**: ระบบส่งอีเมลต้อนรับสมาชิก ยืนยันคำสั่งซื้อ ได้รับชำระเงิน จัดส่งแล้ว (พร้อมเลขพัสดุ) ยกเลิก รอบสมัครรับประจำ เตือนสินค้าใกล้หมด และลืมรหัสผ่าน
- **ลืมรหัสผ่าน**: ส่งลิงก์ไปทางอีเมล ลิงก์ใช้ได้ครั้งเดียวภายใน 1 ชั่วโมง เมื่อตั้งรหัสใหม่หรือเปลี่ยนรหัส อุปกรณ์อื่นที่ล็อกอินอยู่จะถูกออกจากระบบ

**หลังร้าน** (`/admin`)
- ภาพรวม: ยอดขาย คำสั่งซื้อที่รอจัดส่ง สินค้าใกล้หมด และสินค้าขายดี
- จัดการคำสั่งซื้อ: ค้นหา กรองตามสถานะ เปลี่ยนสถานะตามลำดับที่ถูกต้อง ใส่เลขพัสดุ และยกเลิก (ระบบคืนสต็อกให้อัตโนมัติ)
- จัดการสินค้า: เพิ่ม แก้ไข ซ่อน และลบ สินค้าที่เคยมีคนสั่งจะถูกซ่อนแทนการลบ เพื่อให้ประวัติคำสั่งซื้อยังอยู่ครบ
- จัดการโค้ดส่วนลด: ลดเป็นเปอร์เซ็นต์หรือจำนวนเงิน กำหนดยอดขั้นต่ำ ส่วนลดสูงสุด และวันหมดอายุได้
- อัปโหลดรูปสินค้า: ลากวางได้หลายรูป จัดลำดับ หรือลบได้ ระบบตรวจไฟล์จากเนื้อไฟล์จริง รับเฉพาะ JPG/PNG/WebP ไม่เกิน 5 MB
- สมัครรับประจำ: ดูรายการทั้งหมด และยอดประจำต่อเดือนโดยประมาณ
- อีเมล: ดูทุกฉบับที่ระบบส่ง พร้อมตัวอย่างหน้าตา (ใช้ตรวจตอนยังไม่ได้ตั้งค่า Resend ได้ด้วย)
- ปุ่ม "รันงานอัตโนมัติตอนนี้": สร้างรอบสมัครรับประจำ ส่งอีเมลเตือนใกล้หมด และยกเลิกคำสั่งซื้อค้างชำระ (ปกติระบบทำให้เองทุก 30 นาที)

**ความปลอดภัย**
- เซิร์ฟเวอร์คำนวณราคา ส่วนลด และค่าส่งเองทั้งหมด ไม่เชื่อตัวเลขที่ส่งมาจากเบราว์เซอร์
- ตรวจสต็อกและจองสต็อกตอนสร้างคำสั่งซื้อภายใน transaction เดียว คำสั่งซื้อที่ไม่จ่ายเงินภายใน 24 ชั่วโมงจะถูกยกเลิกและคืนสต็อกอัตโนมัติ
- รหัสผ่านเข้ารหัสด้วย bcrypt ใช้ session แบบ httpOnly cookie ป้องกัน CSRF ด้วย SameSite cookie และตรวจ Origin
- จำกัดจำนวนครั้งที่เรียกใช้ (rate limit) ในหน้าล็อกอิน การสั่งซื้อ และแชท ตรวจข้อมูลที่รับเข้ามาทุกช่องด้วย zod ใช้ helmet ตั้ง Content-Security-Policy และ SQL ทุกคำสั่งเป็นแบบ parameterized
- ยืนยันการชำระเงินจาก webhook ของ Stripe ที่ตรวจลายเซ็นแล้วเท่านั้น

## เริ่มใช้งาน (เครื่องตัวเอง)

ต้องมี Node.js 22.13 ขึ้นไป (โปรเจกต์ใช้ SQLite ที่มากับ Node จึงไม่ต้องติดตั้งฐานข้อมูลแยก)

```bash
cd D:\website
npm install
copy .env.example .env      # แล้วแก้ค่าในไฟล์ .env
npm run dev
```

เปิด http://localhost:5173

- บัญชีผู้ดูแลเริ่มต้น: `admin@vitara.local` / `Admin@12345` (ตั้งค่าเองได้ด้วย `ADMIN_EMAIL` และ `ADMIN_PASSWORD` ใน `.env` **ก่อน** รันครั้งแรก)
- โค้ดส่วนลดตัวอย่าง: `WELCOME10`, `VITA100`
- ถ้ายังไม่ได้ใส่คีย์ Stripe การจ่ายผ่านพร้อมเพย์หรือบัตรจะพาไปหน้าชำระเงินจำลอง ซึ่งไม่ตัดเงินจริง
- ถ้ายังไม่ได้ใส่ `ANTHROPIC_API_KEY` แชทบอทจะแนะนำสินค้าจากคำสำคัญในข้อความแทน

## เปิดใช้ AI (Claude)

ใส่คีย์จาก https://console.anthropic.com ลงใน `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

- ระบบใช้โมเดล `claude-opus-5-5` เป็นค่าเริ่มต้น เปลี่ยนได้ด้วย `ANTHROPIC_MODEL`
- เปิด server-side fallback ไว้: ถ้าโมเดลปฏิเสธคำขอ API จะส่งคำขอนั้นต่อให้โมเดลสำรองที่ Anthropic แนะนำโดยอัตโนมัติ
- ถ้าเรียก API ไม่สำเร็จด้วยเหตุผลใดก็ตาม แชทจะใช้การแนะนำจากคำสำคัญแทน ลูกค้าจึงยังได้คำตอบเสมอ
- ระบบส่งแคตตาล็อกสินค้าทั้งหมดไปให้ AI เลือก และเซิร์ฟเวอร์จะตรวจซ้ำว่าสินค้าที่ AI แนะนำผ่านตัวกรองของลูกค้าและมีสต็อกจริง

## เปิดส่งอีเมลจริง (Resend)

ถ้ายังไม่ได้ตั้งค่า ระบบจะไม่ส่งอีเมลออกไปจริง แต่เก็บทุกฉบับไว้ในหน้า **หลังร้าน → อีเมล** ใช้เปิดลิงก์ทดสอบได้ เช่น ลิงก์ตั้งรหัสผ่านใหม่

1. สมัครที่ https://resend.com (มีแพ็กเกจฟรี)
2. เพิ่มและยืนยันโดเมนของร้าน (เพิ่มระเบียน DNS ตามที่ Resend บอก)
3. สร้าง API key แล้วใส่ใน `.env`:
   ```
   RESEND_API_KEY=re_...
   MAIL_FROM=Vitara <orders@โดเมนของคุณ>
   ```
4. รีสตาร์ตเซิร์ฟเวอร์ แล้วดูสถานะ "ส่งแล้ว" หรือ "ส่งไม่สำเร็จ" ในหน้าอีเมลของหลังร้าน

ถ้ายังไม่มีโดเมน ใช้ `onboarding@resend.dev` ทดสอบได้ แต่ Resend จะส่งถึงเฉพาะอีเมลที่ใช้สมัคร Resend เท่านั้น

## เปิดรับชำระเงินจริง (Stripe)

1. สมัคร Stripe แล้วเปิดใช้ PromptPay และบัตรในบัญชีประเทศไทย
2. ใส่ `STRIPE_SECRET_KEY` ใน `.env`
3. สร้าง webhook endpoint ไปที่ `https://โดเมนของคุณ/api/payments/stripe/webhook` เลือก event `checkout.session.completed` และ `checkout.session.async_payment_succeeded` แล้วใส่ signing secret ใน `STRIPE_WEBHOOK_SECRET`
4. ทดสอบบนเครื่องตัวเองด้วย `stripe listen --forward-to localhost:4000/api/payments/stripe/webhook`

## ขึ้นระบบจริง (production)

```bash
npm run build      # สร้างไฟล์หน้าเว็บไว้ที่ client/dist
npm start          # เซิร์ฟเวอร์เดียวให้บริการทั้ง API และหน้าเว็บที่พอร์ต 4000
```

ค่าที่ต้องตั้งใน production: `NODE_ENV=production`, `JWT_SECRET` (สุ่มยาว 32 ตัวขึ้นไป), `APP_URL=https://โดเมนของคุณ`, `ADMIN_PASSWORD` ที่ปลอดภัย และคีย์ Stripe
ถ้าไม่ได้ใส่คีย์ Stripe ร้านจะเปิดให้เลือกเฉพาะเก็บเงินปลายทาง

ควรวางเซิร์ฟเวอร์ไว้หลัง HTTPS reverse proxy (เช่น Nginx หรือ Caddy) และสำรองไฟล์ `data/vitara.db` เป็นประจำ

หรือใช้ Docker:

```bash
docker build -t vitara .
docker run -d -p 4000:4000 -v vitara-data:/data --env-file .env -e NODE_ENV=production vitara
```

## คำสั่งที่มีให้

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | รัน API (รีสตาร์ตเองเมื่อแก้โค้ด) คู่กับหน้าเว็บ Vite |
| `npm run build` | build หน้าเว็บสำหรับ production |
| `npm start` | รันเซิร์ฟเวอร์ production |
| `npm test` | รันชุดทดสอบ API |
| `npm run seed` | **ลบ**สินค้า คำสั่งซื้อ และรีวิวทั้งหมด แล้วใส่ข้อมูลตัวอย่างใหม่ (บัญชีผู้ใช้ยังอยู่) |

## โครงสร้างโปรเจกต์

```
server/src/
  app.js              ตั้งค่า Express, ความปลอดภัย, เส้นทาง API
  config.js           ค่าจาก .env
  db/                 schema ฐานข้อมูล และข้อมูลตั้งต้น
  data/catalog.js     สินค้าตัวอย่าง (แก้หรือลบได้)
  routes/             auth, catalog (สินค้า/รีวิว), shop (ตะกร้า/สั่งซื้อ/ชำระเงิน/แชท), admin
  services/           ตรรกะหลัก: products, cart, orders, payments, ai, recommender
server/test/          ชุดทดสอบ API
client/src/
  pages/              หน้าต่างๆ ของร้าน และ admin/
  components/         Layout, ProductCard, ChatWidget, ui
  context/            สถานะผู้ใช้และตะกร้า
prototype/index.html  ต้นแบบหน้าเดียวเวอร์ชันแรก
```

## ก่อนเปิดขายจริง

- แทนสินค้า แบรนด์ และรีวิวตัวอย่างด้วยข้อมูลจริง (รีวิวตัวอย่างมีป้าย "รีวิวตัวอย่าง" กำกับอยู่) และใส่เลข อย. ของแต่ละสินค้า
- ตั้งค่า Resend และยืนยันโดเมน เพื่อให้อีเมลส่งออกไปจริง
- อัปโหลดรูปสินค้าจริงในหลังร้าน และใส่จำนวนวันที่ทานได้ของสินค้าใหม่ทุกตัว (ใช้คำนวณการเตือนใกล้หมด)
- สำรองทั้งไฟล์ `data/vitara.db` และโฟลเดอร์ `data/uploads` (รูปสินค้า)
- ตรวจข้อความโฆษณาให้เป็นไปตามประกาศ อย. เรื่องการโฆษณาผลิตภัณฑ์เสริมอาหาร
- ตรวจนโยบายความเป็นส่วนตัวในหน้า `/help` ให้ตรงตาม PDPA และวิธีที่ร้านเก็บข้อมูลจริง
